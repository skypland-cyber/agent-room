# 아이소메트릭 관제센터 오피스 (`/office` 바닥 탭)

2026-11-27 · `apps/web/src/components/office/iso/`

바닥 탭을 픽셀 평면도에서 **아이소메트릭 2D 관제센터**로 바꾼 1차 구현이다. 기존 오피스의 데이터·탭·액션·폴링·캐시는 그대로 두고, 그리는 방식과 배치만 바꿨다.

## 무엇으로 그리나

그래픽 자산은 **0개**다. 모든 것은 Canvas 2D 코드로 계산해 그린다.

- 이미지·스프라이트시트·아이콘 파일 없음
- Three.js 같은 3D 엔진 없음
- 폰트는 브라우저 시스템 폰트(`-apple-system`, `Segoe UI`, `Roboto`)만 사용
- 라이선스 비용·출처 표기 의무 없음

아이소메트릭 투영은 `iso.ts`의 두 함수가 전부다.

```
screenX = (gx - gy) * 32
screenY = (gx + gy) * 16
```

타일은 2:1 다이아몬드이고, 가구는 그 다이아몬드를 위로 밀어 올린 상자(윗면 + 좌·우 옆면)다. 벽은 방의 먼 쪽 두 변을 세운 반투명 유리판이다.

## 파일

| 파일 | 역할 |
|---|---|
| `iso.ts` | 투영·역투영, 방 경계 상자, 카메라 맞춤. 캔버스 없이 테스트 가능 |
| `isoPlan.ts` | 6개 공간 + 라운지 + 광장의 좌표, 책상·회의실 pod·휴게 자리, 가구 목록, 클릭 판정 |
| `isoScene.ts` | 서버 payload → 사람마다 설 자리·자세·말풍선·진행률, HUD 숫자(알림·방별 배지·회의실 연결) |
| `isoWalk.ts` | 대표 아바타의 이동·충돌·문 통과·인사 판정. 캔버스 없이 테스트 가능한 순수 산술 |
| `paintIso.ts` | 정적 레이어(바닥·벽·가구·문턱)와 프레임(사람·대표·말풍선·이름표·방 표지) 페인터, 말풍선·이름표 배치 |
| `ControlCenter.tsx` | 캔버스 + HUD + 클릭/호버 + 전체화면 + 상세 패널. 반응형 배치 |

## 그리는 순서

1. `paintStatic` — 배경 그라디언트, 건물 상판, 방별 바닥(체커 타일 + 네온 테두리), 유리 벽, 가구(깊이 정렬). 크기가 바뀔 때 한 번만 그려 오프스크린 캔버스에 담고, 매 프레임은 blit만 한다.
2. `paintFrame` — 사람(발 위치로 깊이 정렬), 방 호버 표시, 말풍선, 이름표, `!` 배지. 글자는 월드 변환을 푼 뒤 화면 좌표로 그려서 어떤 배율에서도 10px로 선명하다.

## 성능

- 정적 레이어는 리사이즈 때만 다시 그린다. 프레임당 비용은 blit 1회 + 도형 수십 개 + 글자 몇 개.
- `requestAnimationFrame` 루프는 탭이 숨겨지면 멈춘다(`visibilitychange`).
- DPR은 2로 제한하고, 캔버스 backing store는 CSS 크기 × DPR로 잡는다.
- 상태 갱신은 400ms마다 한 번(`planIso`), 그 사이 프레임은 이동 보간만 한다.
- 서버 요청은 늘지 않는다. 이미 받은 `overview`만 읽는다.

## 사람이 서는 자리 (서버 값 그대로)

| 서버 상태 | 자리 |
|---|---|
| 승인 대기 카드 보유 | 대표실 (머리 위 `!`) |
| `reviewing` | 회의실 pod 좌석 |
| `working` + 총괄(망고) | 중앙 관제석 콘솔 |
| `working` + 개발(Codex 등) | 개발실 책상 |
| `working` + 그 외 | 분석실 책상 (자리 없으면 광장) |
| `paused` | 라운지 소파 |
| `offline` | 자기 책상, 흐리게 |
| `idle` | 라운지 소파·커피 카운터 (18초마다 자리 이동, 잡담) |

## 대표 아바타 (걷기)

바닥의 유일하게 조작되는 사람이다. 서버 값으로 서는 AI 직원과 달리 위치가 클라이언트에 있고, 규칙은 `isoWalk.ts`에 모여 있다.

- **시작 위치**: 대표실 안, 자기 문에서 한 걸음 들어온 자리(`CEO_SPAWN` = 14.35, 4.35).
- **조작**: PC는 `WASD`·방향키, 모바일은 캔버스 우측 하단의 반투명 D-pad. 입력 중인 `input`/`textarea`와 조합키(Ctrl·Cmd·Alt)는 무시한다.
- **방향**: 화면이 45° 돌아가 있으므로 `→`는 `+gx −gy`로 간다. 대각선은 정규화해서 빨라지지 않는다.
- **속도**: 초당 3.6타일(직원 이동 3.2). 프레임 간격은 0.05초로 상한을 둔다.
- **충돌**: 건물 상판 경계, 높이가 있는 가구(책상·콘솔·소파·선반·서버·화분 등), 그리고 유리가 있는 방의 네 변. 한 번에 못 가면 축을 나눠 미끄러진다.
- **문 통과**: 방마다 문은 하나이고, 문은 벽에 뚫린 통로 사각형(`doorPortal`)이다. 겹쳐 붙은 두 방(대표실↔라운지)도 두 벽의 구멍이 같은 자리에 있어 통과된다. 벽은 그림에 있는 방에만 있다 — 콘솔 플랫폼(`wall: 0`)은 벽도 충돌도 없다.
- **인사**: 2.4타일 안에 AI 직원이 있으면 대표 머리 위에 "안녕하세요, ○○님!"이 뜨고, 그 직원 이름표 옆에 손 흔드는 배지가 붙는다. 직원의 업무 말풍선은 건드리지 않는다.
- **HUD**: 발밑 하단 바에 `대표 · 대표실`처럼 지금 서 있는 구역을 표시한다. 가까운 직원이 있으면 캔버스 좌하단에 `Space · ○○와 대화` 칩이 뜬다(누르면 상세 패널).

## 문·벽·바닥

- 방의 유리 벽은 먼 쪽 두 변에만 그린다. 문이 그 변에 있으면 벽을 잘라 문틀을 세우고, 문턱에 네온 스트립을 깐다(문이 열린 변에 있지 않은 방도 같은 문턱 표시를 받는다).
- 계획 데이터의 문 좌표는 하나의 점이지만, 그리는 쪽과 걷는 쪽 모두 `zoneDoorway()`로 변과 위치를 얻어 같은 구멍을 쓴다.
- 바닥·가구 대비: 방 바닥 판을 상판보다 한 단계 밝게, 가구는 윗면 하이라이트 + 옆면 그라디언트(위는 밝고 아래는 어둡게)로 입체감을 준다. 벽은 유리 그라디언트와 상단 레일·바닥 심을 밝혀 어두운 슬레이트 톤 안에서도 경계가 읽히게 했다.

## 좁은 화면의 글자

폭 520px 미만(아이폰 세로)에서도 **이름표와 말풍선은 항상 그린다.** 대신 `frameTextPlan()`이 두 가지 크기(`FULL_TEXT_METRICS`/`COMPACT_TEXT_METRICS`)를 고른다 — 글자 10px→8.5px, 말풍선 최대 폭 122px→84px, 줄 수 3→2. 방 표지(대표실·개발실…)만 좁은 화면에서 생략하고, 방 목록은 캔버스 아래 칩 줄이 대신한다.

말풍선은 무대 안으로 클램프하고 겹치면 위로 쌓는다. 이름표는 반대로 옆으로 밀며 자리를 찾고(`layoutAgentTags`), 말풍선 상자는 피한다. 대표 이름표를 가장 먼저 배치해 나머지가 그 주변으로 움직인다.

## 클릭

- 캐릭터 → `OfficeAgentPanel` 상세(지시·승인·일시정지)
- 대표실 / 중앙 관제석 → 업무·승인 탭
- 개발실 / 분석실 / 라운지 → AI 직원 탭
- 회의실 pod → 해당 `/r/{code}` (없으면 프로젝트 탭)
- 자료실 → 보관함 탭
- 광장 → 선택 해제
- 대표 아바타를 눌러도 상세 패널은 열리지 않는다(대표는 AI 직원이 아니다). 그 자리의 방 판정만 따른다.
