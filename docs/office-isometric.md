# 아이소메트릭 관제센터 오피스 (`/office` 바닥 탭)

2026-11-28 · `apps/web/src/components/office/iso/`

바닥 탭의 아이소메트릭 오피스. 1차에서 픽셀 평면도를 아이소메트릭 관제센터로 바꿨고,
2차에서 **심즈·타이쿤처럼 구경하는 관찰 모드**(카메라·미니맵·낮밤·카페 존)를 얹었다.
기존 오피스의 데이터·탭·액션·폴링·캐시는 그대로 두고, 그리는 방식과 배치만 바꿨다.

## 무엇으로 그리나

그래픽 자산은 **0개**다. 모든 것은 Canvas 2D 코드로 계산해 그린다.

- 이미지·스프라이트시트·아이콘 파일 없음
- Three.js 같은 3D 엔진 없음
- 폰트는 브라우저 시스템 폰트(`-apple-system`, `Segoe UI`, `Roboto`)만 사용
- 라이선스 비용·출처 표기 의무 없음

아이소메트릭 투영은 `iso.ts`의 두 함수가 전부다.

```
screenX = (gx - gy) * 32
screenY = (gx + gy) * 16
```

타일은 2:1 다이아몬드이고, 가구는 그 다이아몬드를 위로 밀어 올린 상자(윗면 + 좌·우 옆면)다.
벽은 방의 먼 쪽 두 변을 세운 반투명 유리판이고, 창문이 있는 방은 그 판에 창유리가 들어간다.

## 파일

| 파일 | 역할 |
|---|---|
| `iso.ts` | 투영·역투영, 방 경계 상자, 화면 맞춤. 캔버스 없이 테스트 가능 |
| `isoPlan.ts` | 7개 공간 + 휴게실 + 카페 존 + 광장의 좌표, 책상·회의실 pod·휴게 자리, 가구 목록, 클릭 판정 |
| `isoScene.ts` | 서버 payload → 사람마다 설 자리·자세·말풍선·진행률, HUD 숫자(알림·방별 배지·회의실 연결) |
| `isoWalk.ts` | 대표 아바타의 이동·충돌·문 통과·인사 판정. 캔버스 없이 테스트 가능한 순수 산술 |
| `isoRoute.ts` | 방과 방 사이를 잇는 통로 그래프. 직원이 벽을 뚫고 카페로 가지 않게 하는 최단 경로 |
| `isoCamera.ts` | 줌·팬·추적 카메라의 산술. 손가락 아래 지점 고정 줌, 바닥이 화면을 벗어나지 않는 클램프 |
| `isoLight.ts` | 낮·밤 조명. 시각 → `dayness` 한 숫자 → 하늘·유리·창문·램프·그림자 색 |
| `isoReality.ts` | 서버가 보고한 실제 상태(`LIVE`)와 화면 연출(`연출`)의 구분 |
| `isoMinimap.ts` | 미니맵 투영(월드 ↔ 미니맵), 방 모양, 카메라 뷰파인더 |
| `paintIso.ts` | 정적 레이어(바닥·벽·가구·문턱·조명)와 프레임(사람·대표·말풍선·이름표·방 표지) 페인터 |
| `IsoStage.tsx` | 캔버스 + 카메라 + 제스처 + HUD(줌·미니맵·조명·관찰/관리 전환) |
| `IsoMinimap.tsx` | 미니맵 캔버스. 누르면 그 자리로 카메라가 이동 |
| `ControlCenter.tsx` | 두 가지 틀(관찰 모드 / 관리 화면)과 관리 패널 |
| `isoCamera/isoLight/isoReality/isoMinimap/isoRoute.test.ts` | 위 산술의 단위 테스트 |

## 두 가지 틀, 하나의 바닥

| | 관찰 모드 (기본) | 관리 화면 |
|---|---|---|
| 무대 | 화면 전체(`fixed inset-0`), 게임 HUD만 | 페이지 안 카드, 우측에 관리 패널 |
| 캐릭터 클릭 | 상세 카드(상태·업무·진행률) + 카메라 추적 | `OfficeAgentPanel`(지시·승인·일시정지) |
| 방 클릭 | 그 방으로 카메라 이동 | 해당 탭 이동 |
| 전환 | 상단 `관리 화면` 버튼 | 상단 `관찰 모드` 버튼 |

같은 `IsoStage` 인스턴스를 쓰므로 모드를 바꿔도 카메라 위치·대표 아바타 위치·따라가는
대상이 유지된다. 관리 패널은 관찰 모드에서 아예 렌더하지 않는다.

## 실제 상태와 연출 (`isoReality.ts`)

바닥에는 두 종류의 것이 같이 그려진다. 서버가 보고한 사실과, 방이 살아 보이게 하는 연출이다.
둘을 섞지 않기 위해 모든 캐릭터는 하나의 `RealityInfo`로 해석되고, 이름표·상세 카드·명단·미니맵이
같은 값을 읽는다.

| 상태 | 라벨 | 이름표 |
|---|---|---|
| `working` | `LIVE · 업무 중` | 실선 테두리 + `LIVE` 칩 |
| `reviewing` | `LIVE · 검수 중` | 실선 + `LIVE` |
| 승인 대기 | `LIVE · 승인 대기` | 실선 + `LIVE` + 깜빡이는 `!` |
| `paused` | `일시정지` | 실선 + `LIVE` |
| `offline` | `오프라인` | 흐리게 |
| `idle` (휴게실) | `대기 중 · 휴게실 연출` | **점선** 테두리 + `연출` 칩 |
| `idle` (카페) | `대기 중 · 카페 연출` | 점선 + `연출` |
| `idle` (이동 중) | `대기 중 · 휴식 연출` | 점선 + `연출` |

대기 직원의 말풍선은 절대 카드 번호(`T-…`)를 말하지 않는다 — 잡담뿐이다.

## 카메라

- **줌**: 마우스 휠, 두 손가락 핀치, `＋`/`－` 버튼, 더블 탭. 배율 100%–500%, 100%가 전체 보기.
- **팬**: 드래그. 줌 배율과 무관하게 손가락을 따라온다. 바닥이 화면 밖으로 나가지 않게 클램프한다.
- **추적**: 캐릭터를 누르면 그 직원을 따라간다(걷는 동안 카메라가 따라 이동). `따라가기 끄기` 또는 드래그로 해제.
- **리셋**: `⤢` 버튼 또는 `0` 키. 키보드 `+`/`-`는 중앙 기준 줌, `F`는 가까운 직원 따라가기.
- **휴대폰 기본값**: 세로 화면에서는 폭에 맞추면 바닥이 화면의 3분의 1만 차지하므로, 첫 프레임에서
  190%로 밀어 넣어 시작한다. 핀치로 넓게 볼 수 있다.

성능: 카메라는 ref에 있고 줌 퍼센트만 state다(드래그로 60fps 리렌더 없음). 정적 레이어는
제스처가 끝난 뒤 200ms에 한 번 새 배율로 다시 그리고, 그 사이에는 이전 그림을 늘려 그린다.
정적 캔버스는 매번 새로 만들지 않고 같은 것을 덮어쓴다.

## 미니맵

건물 다이아몬드 + 방별 네온 판 + 사람 점(실제 상태는 채운 점, 연출은 빈 링) + 대표 삼각형 +
지금 무대가 보여주는 영역(뷰파인더 사각형). 누르면 그 월드 좌표로 카메라가 이동한다.
260ms마다 갱신한다.

## 낮과 밤 (`isoLight.ts`)

`dayness` 0(밤)~1(정오) 하나가 하늘·상판·바닥 워시·유리·창문 발광·램프 밝기·그림자를 정한다.

- `auto`: 실제 시각. 05:30에 뜨고 19:00에 지며, 각 2시간은 부드럽게 램프를 탄다.
- `day` / `night`: 수동 고정. 상단 ☀️/🌙 버튼이 auto → day → night 순환.
- 밤에는 창문이 따뜻하게 켜지고, 펜던트·스탠드 램프가 바닥에 빛 웅덩이를 만든다.
- 조명은 1/12 버킷으로 키를 만들어, 몇 초 사이의 변화로 정적 레이어를 다시 그리지 않는다.

## 카페 존과 휴게실

- **휴게실 (`lounge`)**: 소파 2개, 낮은 테이블, 커피 카운터, 스탠드 램프, 책장.
- **카페 존 (`cafe`)**: 남쪽 새 윙. 20×4타일. 에스프레소 바(카운터 + 머신 + 메뉴판 + 펜던트 3개),
  바 스툴 3개, 테이블 4개와 의자, 서쪽 끝 암체어, 화분·정수기·스탠드 램프.
  문은 바 정면이 아니라 x=10.6에 있어 들어서자마자 카운터에 막히지 않는다.
- 대기 직원은 26초마다 휴게실과 카페를 오가는 자리로 바뀐다. 순간이동이 아니라 `isoRoute`의
  통로를 따라 **걸어서** 이동한다(휴게실 → 관제석 앞 → 동쪽 복도 → 남쪽 복도 → 카페 문).

## 이동 경로 (`isoRoute.ts`)

방 사이를 잇는 12개 통로 노드와 간선 그래프. 직선으로 가면 자료실·회의실을 뚫고 지나가므로
다익스트라로 최단 경로를 찾고, 방에 들어갈 때는 그 방의 문 허브를 지난다. 카페처럼 긴 방은
방 안의 통로(`aisle`)를 한 번 거쳐 테이블을 밟지 않는다. 그래프의 모든 간선은 벽이 있는 방을
지나지 않는지 테스트로 검사한다.

## 그리는 순서

1. `paintStatic` — 하늘 그라디언트(조명), 건물 상판, 방별 바닥(체커 타일 + 네온 테두리), 유리 벽과
   창문, 가구(깊이 정렬), 조명 워시. 크기·조명·카메라가 멈췄을 때 한 번만 그려 오프스크린 캔버스에 담는다.
2. `paintFrame` — 사람(발 위치로 깊이 정렬), 방 호버 표시, 말풍선, 이름표(+`LIVE`/`연출` 칩), `!` 배지.
   글자는 월드 변환을 푼 뒤 화면 좌표로 그려서 어떤 배율에서도 10px로 선명하다.

## 사람이 서는 자리 (서버 값 그대로)

| 서버 상태 | 자리 |
|---|---|
| 승인 대기 카드 보유 | 대표실 (머리 위 `!`) |
| `reviewing` | 회의실 pod 좌석 |
| `working` + 총괄(망고) | 중앙 관제석 콘솔 |
| `working` + 개발(Codex 등) | 개발실 책상 |
| `working` + 그 외 | 분석실 책상 (자리 없으면 광장) |
| `paused` | 휴게실 소파 |
| `offline` | 자기 책상, 흐리게 |
| `idle` | 휴게실·카페 16개 자리 (26초마다 이동, 잡담) |

## 대표 아바타 (걷기)

바닥의 유일하게 조작되는 사람이다. 서버 값으로 서는 AI 직원과 달리 위치가 클라이언트에 있고,
규칙은 `isoWalk.ts`에 모여 있다.

- **시작 위치**: 대표실 안, 자기 문에서 한 걸음 들어온 자리(`CEO_SPAWN` = 14.35, 4.35).
- **조작**: PC는 `WASD`·방향키, 모바일은 캔버스 우측 하단의 반투명 D-pad. 입력 중인 `input`/`textarea`와
  조합키(Ctrl·Cmd·Alt)는 무시한다.
- **방향**: 화면이 45° 돌아가 있으므로 `→`는 `+gx −gy`로 간다. 대각선은 정규화해서 빨라지지 않는다.
- **속도**: 초당 3.6타일(직원 이동 3.2). 프레임 간격은 0.05초로 상한을 둔다.
- **충돌**: 건물 상판 경계, 높이가 있는 가구, 유리가 있는 방의 네 변. 한 번에 못 가면 축을 나눠 미끄러진다.
- **문 통과**: 방마다 문은 하나이고, 문은 벽에 뚫린 통로 사각형(`doorPortal`)이다. 겹쳐 붙은
  두 방(대표실↔휴게실)도 두 벽의 구멍이 같은 자리에 있어 통과된다. 콘솔 플랫폼(`wall: 0`)은 벽도 충돌도 없다.
- **인사**: 2.4타일 안에 AI 직원이 있으면 대표 머리 위에 "안녕하세요, ○○님!"이 뜨고, 그 직원
  이름표 옆에 손 흔드는 배지가 붙는다. 직원의 업무 말풍선은 건드리지 않는다.

## 좁은 화면의 글자

폭 560px 미만(아이폰 세로)에서도 **이름표와 말풍선은 항상 그린다.** 대신 `frameTextPlan()`이
두 가지 크기(`FULL_TEXT_METRICS`/`COMPACT_TEXT_METRICS`)를 고른다 — 글자 10px→8.5px,
말풍선 최대 폭 122px→84px, 줄 수 3→2. 방 표지(대표실·개발실…)만 좁은 화면에서 생략한다.

말풍선은 무대 안으로 클램프하고 겹치면 위로 쌓는다. 이름표는 반대로 옆으로 밀며 자리를 찾고
(`layoutAgentTags`), 말풍선 상자는 피한다. 방 표지는 무대 밖으로 잘리지 않게 클램프한다.

## 클릭

관찰 모드와 관리 화면에서 같은 캐릭터·방을 눌러도 하는 일이 다르다(위 표 참고).

- 캐릭터 → 선택 + 카메라 추적 (관찰) / 상세 패널 (관리)
- 대표실 · 중앙 관제석, 개발실 · 분석실 · 휴게실 · 카페 → 카메라 이동 (관찰) / 해당 탭 (관리)
- 회의실 pod → 카메라 이동 (관찰) / `/r/{code}` (관리, 없으면 프로젝트 탭)
- 자료실 → 카메라 이동 (관찰) / 보관함 탭 (관리)
- 광장 → 선택 해제 + 추적 해제
